# Copilot Instructions — Stream Deck Cloudflare Utilities

## Agent Workflow (agents-template v0.16.0)

This project uses the **agents-template**. `AGENTS.md` is the authoritative operating system —
read it first. Key non-negotiables:

- **TDD**: commit a failing `test(scope)` before the `feat|fix(scope)` implementation.
- **Worktrees**: all work happens on a worktree branch; never commit to `main`.
- **Sentinel**: before any merge, spawn a sub-agent with `docs/SENTINEL.md` as its system prompt
  to review the PR — no merge without an APPROVED/CONDITIONAL verdict.
- **Companion docs**: `docs/ARCHITECTURE.md`, `docs/TESTING-STRATEGY.md`,
  `docs/DEVELOPMENT-WORKFLOW.md`, plus `DECISIONS.md` and `LEARNINGS.md`.
- **Stream Deck specifics** (hardware-test release gate, Cloudflare API rules, UI rules) are in
  AGENTS.md §Stream Deck Project Rules and the `.github/` guides.

### After Significant Work — Contribute Back

After completing significant work (new features, bug fixes, workarounds, testing discoveries),
**proactively offer to write new learnings back to the template repo**.

See `AGENTS.md` for the full contribution protocol.

### Pre-Release Gate — MANDATORY

**Never tag, push, or create a release without the user testing on their physical Stream Deck
first.** The Stream Deck CLI (`validate`, `restart`) only checks manifest schema and plugin
loading — it cannot verify runtime behavior, UI rendering, or key display. Always ask the
user to test on device and wait for explicit confirmation before releasing.
